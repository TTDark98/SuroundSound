================================================================================
SOUND-TO-BEAT ANDROID APPLICATION: PHASED IMPLEMENTATION PLAN
================================================================================
Based on: Sound_to_Beat_Android_Blueprint_v1.pdf (Blueprint v1.0)
Target Platform: Android 12+ (API level 31 minimum, targeting API level 36 for Google Play 2026 compliance)
Language: Kotlin only (No C++, Java, or Python required)
Architecture: Clean Architecture + MVVM + Jetpack Compose + Single Audio Streaming Pipeline
Audio Engine: Custom Offline DSP Engine running on background coroutine dispatchers

--------------------------------------------------------------------------------
CORE ARCHITECTURAL PRINCIPLES & CONSTRAINTS (FACT-CHECKED)
--------------------------------------------------------------------------------
1. Source-Derived Sound Only:
   - Every musical layer is strictly derived from user-provided audio (max 10s per source).
   - Zero synthetic oscillators/instruments, zero bundled sample packs, zero cloud AI APIs.
   - 100% offline-first execution.
2. Audio Architecture (Single Stream vs Multi-Track):
   - Rather than creating multiple concurrent AudioTrack instances (which causes hardware resource exhaustion and sync drift), the engine will implement a unified software mixer buffer in Kotlin that renders mixed PCM chunks into a single low-latency AudioTrack.
3. Audio Encoding Reality Check:
   - Android MediaCodec provides hardware/platform decoding for MP3, AAC, FLAC, and WAV.
   - Android platform DOES NOT mandate or provide a native MP3 ENCODER via MediaCodec (attempting MediaCodec.createEncoderByType("audio/mpeg") throws IOException on standard devices).
   - Solution for MP3 export in 100% Kotlin: Embed a pure Kotlin/Java MP3 encoder (e.g. LAME port) or provide uncompressed WAV (always supported) + AAC/M4A via native MediaCodec, while evaluating pure Kotlin MP3 encoding for Phase 7.
4. Storage & Privacy:
   - Storage Access Framework (SAF) / ActivityResultContracts.GetContent() ensures zero READ_MEDIA_AUDIO or READ_EXTERNAL_STORAGE permissions are needed.
   - Microphone permission (RECORD_AUDIO) requested contextually at runtime with clear user guidance.
   - Playback stops strictly when app enters background or screen locks.

PHASE 1: SOURCE CAPTURE, AUDIO IMPORT & LOCAL PERSISTENCE SKELETON
--------------------------------------------------------------------------------
Goal: Implement reliable microphone recording and local audio import adhering strictly to the 10-second rule.
Deliverables:
  1.1 Microphone Capture Pipeline:
      - AudioRecord wrapper reading 16-bit PCM at 44.1 kHz (mono/stereo).
      - Dynamic countdown timer starting at 0s, warning at 8s, auto-stopping at exactly 10.0s.
      - Runtime permission handling (RECORD_AUDIO) with graceful denial recovery.
  1.2 Local Audio Import & Trimming:
      - SAF file picker integration (ActivityResultContracts.GetContent("audio/*")).
      - Audio decoder utilizing MediaExtractor + MediaCodec to decode any source format (WAV, MP3, AAC/M4A) into raw 16-bit PCM samples.
      - Range-selector UI for imported audio exceeding 10 seconds (enforcing 10s maximum window).
  1.3 Local Storage Skeleton:
      - Internal app-specific storage directories for raw PCM source caches.
      - Base project entity schema (metadata, source list, creation timestamp).
Exit Gate (Milestone Gate A):
  - Microphone capture and file imports successfully decode into PCM arrays capped at 10.0 seconds.

--------------------------------------------------------------------------------
PHASE 2: PLAYBACK PIPELINE & VISUAL FOUNDATIONS
--------------------------------------------------------------------------------
Goal: Establish low-latency audio playback and reactive UI components.
Deliverables:
  2.1 PCM Playback Engine:
      - Low-latency AudioTrack configuration (AudioAttributes.FLAG_LOW_LATENCY / PERFORMANCE_MODE_LOW_LATENCY).

Exit Gate:
  - Recorded/imported audio plays back crisply without stuttering and halts cleanly on backgrounding/lock.

--------------------------------------------------------------------------------
PHASE 3: SOUND DNA EXTRACTION & HEURISTIC ENGINE
--------------------------------------------------------------------------------
Goal: Implement local audio feature extraction without any external cloud services.
Deliverables:
  3.1 Sound DNA Feature Extractor (Offline DSP):
      - 1. RMS Energy: Root-mean-square calculation across time frames.
      - 2. Transient Strength: Peak-to-average onset detection and attack rate.
      - 3. Spectral Brightness (Centroid): FFT-weighted center of gravity of frequency spectrum.
      - 4. Dominant Frequency: Peak FFT magnitude bin estimator.
      - 5. Decay Time: Decay rate measurement from peak onset down to -20dB/-60dB threshold.
      - 6. Spectral Flux: Frame-to-frame spectral difference metric.
  3.2 Intuitive Descriptors & Visuals:
      - Heuristic mapping linking metrics to descriptive badges (e.g., "Punchy", "Bright", "Resonant", "Metallic", "Noisy").
      - Audio suitability inspection: Detect near-silent, severely clipped, or DC-offset audio with warning and option to proceed or re-record.
  3.3 Primary-Source Recommendation:
      - Ranking heuristic for multi-source projects based on transient clarity and harmonic stability.
Exit Gate (Milestone Gate B, Part 1):
  - All 6 Sound DNA metrics calculate in under 500ms on a 10s clip and render in the UI with intuitive badges.

--------------------------------------------------------------------------------
PHASE 4: DSP TRANSFORMATION ENGINE & THE 5 CREATIVE MODES
--------------------------------------------------------------------------------
Goal: Implement the 10 source-derived audio transformations and generate mode previews.
Deliverables:
  4.1 The 10 Offline DSP Transformations:
      - 1. Sample Slicing: Transient-based or beat-division segment isolation.
      - 2. Pitch Shifting: Clean resampling or WSOLA / granular pitch transposition.
      - 3. Playback Speed & Stretching: Time stretching decoupled from pitch.
      - 4. Filtering: State-variable / biquad filters (Low-Pass, High-Pass, Band-Pass, Resonant Peaking).
      - 5. Distortion & Bit Reduction: Soft clipping, wave-shaping, and bit-depth quantization.
      - 6. Delay & Echo: Ring buffer delay with feedback attenuation.
      - 7. Reverb: Freeverb / Schroeder-Moorer comb and allpass reverberation.
      - 8. Reverse Playback: Inverted sample buffer rendering.
      - 9. Retrigger & Stutter: Sub-division loop buffering (1/8th, 1/16th, 1/32nd note stutters).
      - 10. Granular Transformation: Windowed grain emitter with randomized position/pitch jitter.
  4.2 Creative Modes Preset Generator:
      - Industrial: Heavy bit-reduction, distortion, aggressive filtering, metallic short delays.
      - Rhythmic: Sliced transients, snappy envelopes, rhythmic retriggering, punchy filtering.
      - Melodic: Tuned pitch-shifted slices, resonant band-pass filtering, pitched granular pads.
      - Ambient: Long granular time-stretching, diffuse reverb, soft low-pass filtering, reversed layers.
      - Glitch: Chaotic slicing, stutter bursts, extreme bit crushing, erratic reverse playback.
  4.3 Transformed-Sound Preview Flow:
      - Adaptive initial preview count based on Sound DNA.
      - On-demand rendering for non-primary modes.
Exit Gate (Milestone Gate B, Part 2):
  - All 10 transformations run offline in Kotlin; mode previews generate smoothly and audibly transform user sound.

--------------------------------------------------------------------------------
PHASE 5: BEAT-LOOP SEQUENCER & REAL-TIME EDITING ENGINE
--------------------------------------------------------------------------------
Goal: Generate looping beats and provide an interactive step-sequencer editor.
Deliverables:
  5.1 Loop Generator:
      - Automatic arrangement generation mapping transformed slices onto musical layers (Kick/Bass role, Perc/Snare role, Hi-hat/Texture role, FX/Accent role).
      - Tempo estimation via peak pulse detection with fallback to default BPM (e.g. 120 BPM).
  5.2 Interactive Step Sequencer:
      - Configurable step grid (e.g., 8, 16, 24, 32 steps).
      - Visual step toggle matrix with active step playhead animation.
      - The 9 confirmed editing controls:
        1. Tempo (BPM control)
        2. Rhythm Pattern
        3. Beat Density
        4. Pitch transposition
        5. Effect Intensity
        6. Layer Volume / Mix
        7. Loop Length (allowing loops > 10 seconds)
        8. Timing / Swing
        9. Manual Sound Placement (drag/tap slice onto grid step)
  5.3 Live-vs-Regenerate Audio Handling:
      - Live parameter updates: Volume, pan, tempo playback rate, simple filter cutoff.
      - Regenerate-on-stop updates: Structural slicing, complex granular re-renderings.
Exit Gate (Milestone Gate C):
  - Sequencer plays seamless repeating loops with live step editing and controllable swing/tempo.

--------------------------------------------------------------------------------
PHASE 6: PERFORMANCE PADS & MULTI-SOURCE INTEGRATION
--------------------------------------------------------------------------------
Goal: Provide real-time finger-drumming pads and support multiple sound sources per project.
Deliverables:
  6.1 Playable Sound Pads:
      - Auto-populated pads mapped to transformed source slices.
      - User re-assignment UI allowing custom slice/effect mapping per pad.
      - Low-latency touch response with confirmed polyphonic / overlapping playback (taps ring out naturally without cutting off previous hits).
  6.2 Multi-Source Project Management:
      - Ability to add, record, or import secondary audio sources.
      - Source role management (Primary Source drives mode analysis; secondary sources adopt the same mode).
      - "Update Beat" vs "Preserve Current Arrangement" prompt upon adding/removing a source.
Exit Gate (Milestone Gate D):
  - Pads trigger derived sounds with instant tactile response alongside the playing sequencer; multi-source imports coexist without desynchronization.

PHASE 7: LOCAL PROJECT REPOSITORY, AUTOSAVE & AUDIO EXPORT
--------------------------------------------------------------------------------
Goal: Enable project persistence and offline export/sharing.
Deliverables:
  7.1 Project Persistence & Autosave:

  - Projects autosave and reopen flawlessly in airplane mode; exported WAV/MP3 files play properly in external music players.
